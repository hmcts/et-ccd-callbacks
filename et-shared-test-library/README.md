# @et-shared-test-library/core

Shared TypeScript Playwright test utilities for Employment Tribunal projects.

This package contains reusable test helpers, page objects, fixtures, API utilities, data factories, and resource files that are used across ET UI/API test suites.  
It is designed to be consumed both:

- inside this repository (`et-ccd-callbacks`) during local/CI test execution, and
- from other repositories by installing `@et-shared-test-library/core`.

## What this package provides

- Reusable Playwright-oriented helpers and common test abstractions
- Shared test data/resource payloads under `resources/`
- Common config and fixture exports for consistent usage across repos
- A publishable package surface via `dist/` + package `exports`

## Package structure

- `src/` — TypeScript source code for shared utilities
- `resources/` — static test payloads/files (included in npm package)
- `dist/` — compiled output (generated by build; not committed)
- `package.json` — package metadata, exports, scripts

## Exports

From `package.json`:

- `@et-shared-test-library/core`
- `@et-shared-test-library/core/config`
- `@et-shared-test-library/core/fixtures/common`
- `@et-shared-test-library/core/resources/*`

## Requirements

- Node.js `>=20`
- Yarn `4.x` (project uses Yarn Berry)
- Peer dependencies supplied by consumer project:
    - `@playwright/test`
    - `playwright-core`
    - `@hmcts/playwright-common`

## Install

### In another repository

```bash
yarn add @et-shared-test-library/core
```

### In this repository (workspace/portal development flow)

Install dependencies from repository root:

```bash
yarn install
```

Build the shared package before running tests that consume it:

```bash
yarn build:shared
```

## Build, test, lint (inside `et-shared-test-library`)

```bash
yarn install
yarn build
yarn test
yarn lint
yarn typecheck
```

## Usage example

```ts
import { users, config, CaseTypeLocation } from '@et-shared-test-library/core';
```

Resource files are packaged and available via package exports (for example under `@et-shared-test-library/core/resources/...`), so consumers in other repos do not need local relative paths to this repository.

## Publishing

Typical release flow:

1. Update `version` in `package.json`
2. Build and test the package
3. Publish to registry

```bash
yarn build
npm publish
```

## Notes for contributors

- Keep reusable logic in this package, not in consuming test repos.
- Prefer stable, package-relative resource access patterns for cross-repo compatibility.
- Do not commit `dist/`; it is generated by `yarn build`.
- If consumer tests fail with missing shared module entry points, ensure shared package build has been executed (`yarn build:shared` from repo root in this project).
